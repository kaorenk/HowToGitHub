# HowToGitHub 🚀

GitHubを用いた実践的なワークフローとGit操作を段階的に学ぶハンズオン形式のロードマップです。  
**`my-progress`** など、何らかの進捗記録用**ブランチ**を作成し、
課題を達成したら、チェックボックスを `[x]` に更新して進捗を記録しましょう。


## 📌 ブランチ運用ルール

本リポジトリでは、チュートリアル教材の改善と学習の実践をシンプルに進めるため、以下のブランチ構成で運用します。

### 主要ブランチ
- **`main`**: 正式リリース・テンプレート用。
- **`develop`**: 検証・統合用。解説の加筆はすべてここへ集約します。
- **`feature/`**: ドキュメント修正用。
- **`my-progress`**: 自分専用の進捗記録用。

### タグ運用の基本ルール
バージョニングとリリースの目的に応じて、タグを付与する対象ブランチを切り分けます。

| 対象ブランチ | タグの種類 | 命名規則の例 | 用途・意味 |
| :--- | :--- | :--- | :--- |
| **`main`** | 正式リリース / 配布用タグ | `v0.1.0`, `v1.0.0` | 教材として完成・確定したスナップショット用 |
| **`develop`** | プレリリース / 検証タグ | `v0.1.0-alpha`, `v0.1.0-beta` | ドキュメント修正の集約 |

### ドキュメント修正用の作業ブランチ運用
教材の加筆修正を行う場合は、すべて `develop` から **`feature/<作業内容>`** ブランチを切って作業します。

- **命名規則**: `feature/<作業内容>` （例: `feature/phase1-basic-workflow`）
- **マージ先**: `develop`
- **作業内容**: 解説文の追記など、気になった修正はすべて同じブランチ内で同時にコミットして構いません。

> **💡 develop、mainブランチ（配布用）への反映について:**  
> developにプルリクし、マージで集約したら、 `main` 宛てにプルリクしてマージします。

## 使い方
1. 本リポジトリを Fork または Clone して学習環境を用意します。
2. `develop`（または `main`）から進捗記録用の `my-progress` ブランチを作成して切り替えます。
3. Phase 1 から順に `docs/` 配下の手順に従って検証を進め、完了した項目に `[x]` をつけて記録します。
