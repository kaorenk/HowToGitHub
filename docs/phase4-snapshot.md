### Phase 4: タグを活用したスナップショット復元体験 (v0.4.0)
Git のタグが「特定の歴史を固定して再現できるスナップショット」であることを確認するため、未マージの実験的コミットにタグを打って GitHub へ単体プッシュし、作業ブランチを完全に破棄した状態からタグのみを頼りに当時の環境を復元する挙動を体感します。

> **「タグさえ残しておけば、その瞬間の世界をいつでも100%復元できる(タイムトラベル検証)」**
> - **ブランチ（動くしおり）**: コミットを追加すると先端（HEAD）が前に進みます。役目が終われば削除される前提の一時的な「作業ルート」です。
> - **タグ（絶対に動かない記念碑 / アンカー）**: 一度コミットに打ち込むと、その位置に永久に固定されます。作業ブランチを削除しても、タグが指すコミットデータそのものが消えることはありません。

- [ ] **実験用ブランチの作成とコミット**:
  - [ ] `develop` から実験用ブランチ（例: `exp/temporary-feature`）を作成してチェックアウト
  - [ ] 検証用の新規ファイル（例: `memo.txt`）を作成・コミット（※`develop` や `main` にはマージしない）
- [ ] **アーカイブタグの作成とリモートへの単体プッシュ**:
  - [ ] ログ画面（Show log）から上記コミットを右クリックし、「タグを作成」を選択（例: `archive/exp-feature`）
  - [ ] プッシュ画面で作業ブランチは送らず、「タグ（Tags）」のみを指定して GitHub へプッシュ
  - [ ] GitHub のリポジトリ画面で「Tags」タブを開き、ブランチ一覧にはないコミットがタグとしてリモート上に保存されていることを確認
- [ ] **作業ブランチの完全破棄**:
  - [ ] ローカル環境を `develop` に切り替え（チェックアウト）
  - [ ] 切り替え画面のブランチ一覧（`...` ボタン）から未マージの `exp/temporary-feature` をローカルから強制削除
  - [ ] ローカルおよびリモートの双方から作業ブランチが消滅した状態（タグのみが残る状態）を確認
- [ ] **タグからの完全復元検証**:
  - [ ] ログ画面で残されたタグ `archive/exp-feature` を右クリック →「このバージョンからブランチを作成」を選択
  - [ ] 復元用ブランチ名（例: `restore/exp-feature`）を設定し、「新しいブランチをチェックアウト」にチェックを入れて作成
  - [ ] フォルダ内に先ほど破棄したはずのファイル（`memo.txt`）が寸分狂わず復元されていることを確認
- [ ] **一時環境の後片付け**:
  - [ ] ローカル環境を最新の `develop`（または `main`）へ切り替え
  - [ ] 切り替え画面から確認用に作成した復元用ブランチ（`restore/exp-feature`）を削除
  - [ ] 「ブランチが消えても、タグさえプッシュされていればいつでも過去の状態を再生成できる」ことを理解
